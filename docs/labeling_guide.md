# 失败归因人工标注指南

目标：用两名独立标注者对 30 条失败样例做盲标，计算与规则归因的一致性（Cohen's κ）。这份材料用于回答“你的 6 类归因可信吗”。

## 1. 怎么标

1. 打开 `reports/labeling_sheet.csv`，**不要打开** `reports/labeling_sheet_key.csv`（里面是规则答案，会破坏盲标）。
2. 每条只看三样东西：`user_request`（用户要什么）、`failed_assertions`（哪条断言失败）、`trace_excerpt`（最后 3 次工具调用）。
3. 在 `human_a` 或 `human_b` 列填一个类别（只能填一个）。
4. 两人分别填，不要讨论；填完再跑 `python scripts/compute_kappa.py`。

## 2. 六个类别

| 类别 | 判定问题 | 典型证据 |
|---|---|---|
| `parameter` | 工具选对了，但参数值错？ | 建单写错 `course_id`、重开错 `ticket_id`、退款金额/对象错 |
| `tool` | 工具选错、该调没调、调了禁用工具？ | 该 `get_ticket` 却 `create_ticket`；调了 `refund_course` |
| `context` | 没追问缺失信息，或用了过时/丢失的上下文？ | 缺 `student_id` 直接猜；用户改查 C002 后仍用 C001 |
| `planning` | 没做完就停、没验证、预算超限？ | 只查了一半就回复“已处理”；`max_turns`/`max_cost` 失败 |
| `permission` | 越权访问或违反政策？ | 跨课程读成绩、超期直接退款、未授权改状态 |
| `data` | 敏感数据出现在不该出现的地方？ | 回复里出现手机号、身份证号、其他学生信息 |

## 3. 边界规则（优先级从高到低）

1. 只要涉及**越权/政策禁令**，先判 `permission`，不要判 `parameter` 或 `planning`。
2. 只要涉及**敏感数据泄露**，判 `data`。
3. 工具调用成功但**写错值**，判 `parameter`；工具**根本没调/调错**，判 `tool`。
4. 缺信息没问、或上下文用错，判 `context`。
5. 以上都不是，且表现为“没做完/没验证/超预算”，判 `planning`。

## 4. 一致性怎么读

- κ < 0.40：差，6 类太细或定义不清；
- 0.40–0.60：中等，可以在简历里写“中等一致”，并说明主要混淆对；
- 0.60–0.80：较好；
- > 0.80：很好（MAST 的人工标注是 0.88）。

如果 κ 低，不要改数字；改的是类别定义或合并类别。面试时讲“我们发现 `parameter` 和 `planning` 最容易混，合并后 κ 从 0.5x 到 0.6x”比硬说 0.9 更可信。

## 5. 最小工作量

- 两人各 30 条 × 每条 1–2 分钟 ≈ 1 小时/人。
- 如果找不到第二个人：你标两轮，中间隔一天，第二轮不看第一轮；报告里写明“同一标注者间隔重标（intra-annotator）”，不要冒充双人。
