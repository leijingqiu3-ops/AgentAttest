# 看板与演示视频

## 1. 看板

- 文件：`reports/dashboard.html`（单文件，数据内嵌，离线打开）
- 入口：双击根目录 `打开看板.bat`
- 生成：`node work/build_dashboard.mjs`，数据源 `reports/dashboard_data.json`

六个分区：

| 分区 | 回答的问题 |
|---|---|
| 概览 | 一共跑了多少、检出多少、误报多少、κ 多少 |
| 用例 | 同一条用例 7 种跑法，断言、工具轨迹、最终回复 |
| 检测 | 六类故障注入多少、检出多少 |
| 对照 | 自研靶子 vs LangGraph ReAct，同题 120 次 |
| 真实案例 | 70 条真实 badcase 的来源、分层与样例 |
| 归因 | 93 条失败的主标签分布与 κ |

交互：点场景族 → 点用例 → 点跑法；键盘 ← → 切换跑法；右上角切深色。

## 2. 演示视频

- 文件：`outputs/demo_dashboard.mp4`（48 秒，1440×900，无音轨）
- 内容：真实录屏，不是后期动画。首屏 → 用例 → 注入检出 → LangGraph 对照 → 真实案例 → 归因 → 深色模式。

## 3. 两个容易被追问的口径

- **91 / 91**：分母是实际触发的注入次数。early_stop 只在 Agent 发起工具调用后触发，直接答复的 4 条 run 不进分母。
- **93 条失败**：93 = 91 条注入失败 + 2 条故障不适用场景族的自然失败。检出率按实际注入算，归因只对注入失败算一致性。旧版 97 条含 4 条成本误判，已降级为 advisory。
- **44 / 93 可拦**：把同样的规则回放到已有 trace，39 条在执行前拦下、5 条靠出口脱敏；187 条通过的 trace 误伤 0。这是反事实上限，不等于任务成功率。
- **κ = 0.80**：规则归因 vs 人工盲标，n=30，95% CI 0.64–0.96。不是人工 vs 人工的 1.00。
