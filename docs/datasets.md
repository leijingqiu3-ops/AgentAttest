# 公开数据集适用性（实测筛选，不是引用清单）

目标：找一个**外部**数据集，能独立验证"工具调用级失败 + 权限/PII 标签"。结论：本地下载的 8 个公开集都不满足，因此本项目的数字仍只来自合成用例与注入目录，不能声称有外部基准。

| 数据集 | 实际内容（已拆开看） | 为什么没用于评分 |
|---|---|---|
| `agent-security-guardrails-eval` | 1,018 条，`blocked` 852 / `allowed` 166；字段只有 `text` + `action`，内容是仇恨/危险内容问答 | 它标的是**内容安全**，不是工具调用越界。我们的层在执行前看工具与参数，不看措辞。若用"是否提到 jailbreak/system prompt"划子集，会与本项目的正则同义反复，测出 100% 也没有信息量 |
| `agentharm` | 44 条公开有害行为（README 自述），工具是网页/邮件类 | 行为与工具都不在教务域；它的危害来自"做了什么"，我们的靶子没有这些工具，接过来只能得到"白名单挡掉了不存在的工具"这种废话结论 |
| `agent-failure-recovery-benchmark` | 22,573 条合成恢复轨迹；`failure_type` 是域内枚举（导航/多智能体/物理/规划），带 `recovery_action` | 标签空间是"能不能恢复、下一步做什么"，不是"这次失败属于哪一类"；没有权限、PII、参数错这些类 |
| `failed-agent-trajectory` | 只有一个 id 列表文件，外加 551 字节的 `trajectory.json` | 没有轨迹正文，无法评估 |
| `mcp-agent-trajectory-benchmark` | 38 条，财务/SQL 类 MCP Agent 会话摘要 | 没有失败标签，也没有工具参数级记录 |
| `tau-bench-tiny` | 零售域单文件 parquet（约 70KB 切片） | 有工具与用户交互，但判定是任务奖励，不含权限/PII/规划这类失败标签；改造成本高于信息量 |
| `agentbench-os` | 单文件 parquet 切片（约 52KB），未展开 | 操作系统任务，域不匹配 |
| `swe-bench-lite` | 单文件 test parquet（约 1.1MB），软件缺陷修复 | 域不匹配；判定是测试通过与否，不是行为审计 |

## 什么样的数据才能验证这个项目

1. 业务 Agent 的**工具调用轨迹**（含每次调用的工具名、参数、返回、终态）；
2. 每条轨迹有**失败标签**，且标签能映射到权限 / 参数 / 工具 / 上下文 / 规划 / 数据六类之一；
3. 最好有**独立人工标注**，而不是由同一套规则生成。

现有 `data/badcases.xlsx`（70 条平台 badcase）只提供场景与描述，不提供上面第 1、2 项，所以它只用于划分场景族，不能当外部验证集。这也是 README 里"40 条用例全部是 `synthetic_seed`"这条局限的来源。
